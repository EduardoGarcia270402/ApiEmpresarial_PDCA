1. QUÉ SE HIZO
────────────────────────────────────────────────────────────────────────────────

Se inicializó el proyecto SPA completo con la siguiente stack:

  • React 19 + TypeScript 6 (Vite 8 como bundler)

  • React Router DOM v7 (enrutamiento SPA con rutas protegidas)

Además del scaffolding base, se dejó toda la capa de integración con
el backend ya implementada, lista para conectar cuando los endpoints

3. DECISIONES TÉCNICAS Y JUSTIFICACIONES
────────────────────────────────────────────────────────────────────────────────

  ┌─ JWT en sessionStorage (no localStorage) ───────────────────────────────┐
  │ Justificación: sessionStorage se limpia al cerrar la pestaña, lo cual  │
  │ reduce la ventana de exposición del token. La especificación §12       │
  │ indica JWT con expiración de 2h; sessionStorage complementa eso.      │
  │ localStorage persistiría el token entre sesiones, lo cual no se desea. │
  └────────────────────────────────────────────────────────────────────────┘

  ┌─ Interceptor Axios: 401 → redirect a /login ───────────────────────────┐
  │ Justificación: Evita que el usuario vea pantallas rotas si el JWT      │
  │ expira. El interceptor limpia el token y redirige automáticamente.     │
  │ Se excluye /login del redirect para evitar bucles infinitos.           │
  └────────────────────────────────────────────────────────────────────────┘

  ┌─ Proxy de Vite (/api → localhost:8080) ─────────────────────────────────┐
  │ Justificación: Elimina problemas de CORS en desarrollo local. En       │
  │ producción se usa VITE_API_URL apuntando al dominio de Render.         │
  └────────────────────────────────────────────────────────────────────────┘

  ┌─ Tailwind CSS v4 con @tailwindcss/vite ─────────────────────────────────┐
  │ Justificación: Tailwind v4 eliminó la necesidad de PostCSS config y    │
  │ tailwind.config.js. El plugin de Vite es la integración recomendada.   │
  │ Resultado: 0 archivos de configuración adicionales.                    │
  └────────────────────────────────────────────────────────────────────────┘

  ┌─ Tipos alineados con el contrato del backend (§7 y §8) ────────────────┐
  │ Justificación: Los tipos en src/types/index.ts replican exactamente    │
  │ los DTOs y modelos documentados en la Especificación Técnica para      │
  │ garantizar 0 discrepancias en la integración.                          │
  └────────────────────────────────────────────────────────────────────────┘

  ┌─ ProtectedRoute con Outlet pattern ─────────────────────────────────────┐
  │ Justificación: Usa el patrón Layout Route de React Router v7. Todas   │
  │ las rutas hijas heredan la protección sin repetir lógica.              │
  └────────────────────────────────────────────────────────────────────────┘

  ┌─ Accesibilidad en componentes ──────────────────────────────────────────┐
  │ Input.tsx usa aria-invalid y aria-describedby para errores.            │
  │ Alert.tsx usa role="alert" para lectores de pantalla.                  │
  │ Button.tsx desactiva correctamente con disabled + cursor-not-allowed.  │
  └────────────────────────────────────────────────────────────────────────┘
